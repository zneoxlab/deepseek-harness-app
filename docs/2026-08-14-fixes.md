# 2026-08-14 修复记录：连接失败 + 标题栏融合

## 问题 1：App 显示"localhost 拒绝连接"（ERR_CONNECTION_REFUSED）

### 根因
`src-tauri/Cargo.toml` 的 tauri 依赖**缺少 `custom-protocol` feature**。
Tauri 2 在 Windows 上：没有 `custom-protocol` 时 release 构建**无法嵌入
frontendDist**，运行时回退到 `devUrl`（`http://localhost:1420`）→ 无服务 → 拒绝连接。

之前正常是因为用户用 `npm run tauri build`（tauri CLI 自动启用），
而我直接用 `cargo build --release` 构建就没有该 feature。

### 修复
```toml
tauri = { version = "2", features = ["tray-icon", "custom-protocol"] }
```
验证：exe 嵌入 dist（splash 深色 UI 正常加载），CDP 确认页面 URL 为
`http://127.0.0.1:3080/` 且 fetch 200。

### 附加修复：bin.js 直接 spawn 失败
npm 全局安装的 dsh 入口是 `bin.js`，Windows 无法直接 spawn .js 文件
（旧报错"启动 dsh web 失败"）。`spawn_dsh_web` 现在对 .js 入口用
`node <bin.js> --profile dsh-app --port 0` 执行。

## 问题 2：标题栏融合（Windows 缩小/放大/关闭 + 标题 → WebUI）

### 实现
1. `tauri.conf.json`：窗口 `"decorations": false`（隐藏原生标题栏）+ `"shadow": true`
2. Rust 新增 4 个窗口命令：`window_minimize` / `window_toggle_maximize` /
   `window_close`（触发托盘隐藏）/ `window_start_dragging`
3. splash 阶段：`src/TitleBar.tsx` 组件（dist 内，连接时可见）
4. 官方 UI 阶段：bridge client `mountTitleBar()` 注入 `#dsh-app-titlebar`
   （fixed 顶部 36px，拖拽 + 标题 + 三按钮），官方 `#root` 下移 36px
5. 浏览器环境（无 `window.__TAURI_INTERNALS__`）不注入，保留原生标题栏

### IPC ACL（关键坑）
Tauri 2 对**远程页面**（官方 UI 是 `http://127.0.0.1:*`）默认拒绝所有 IPC：
`Command window_toggle_maximize not allowed by ACL`。

修复：
- `build.rs`：`AppManifest::commands(&[...])` 为 6 个 app 命令生成
  `allow-<command>` 权限
- `capabilities/default.json`：permissions 加 6 个 allow 权限；
  `"remote": {"urls": ["http://127.0.0.1:*"]}` 允许本地 dsh web 页面调用
  （`local` 与 `remote` 并存，splash 不受影响）

## 问题 3：复用判定

App 只复用**带桌面桥**的 3080 实例（HTTP GET `/dsh-app/status` 返回
`{"ok":true}`）；用户手动起的普通 `dsh web` 会被无视，App spawn 自己的
`dsh-app` profile 实例（随机端口），保证标题栏/设置融合始终可用。
ServerState 现在记录 `(Child, url)` 以记住随机端口。

## 问题 4：清理（2026-08-14 第二轮）

### node 控制台弹窗
Rust spawn `node <bin.js>`（检测/启动 dsh）时 Windows 会弹出黑色控制台窗口。
修复：新增 `no_console(cmd)` 辅助函数，对所有子进程

设置 `CREATE_NO_WINDOW` (0x08000000)。

### 插件报错 `createDshAppSectionStore is not a function`
原因：client bundle 里 settings 融合部分依赖 shell 模块表里的
`@deepseek-ai/dsh-client-runtime` 的 `defineStore`，运行时导出不匹配导致
apply() 抛错，整个插件 client 端被标记失败。

处理（按用户要求删除无用部分）：
- 插件精简为**只做标题栏融合**：client 端纯 DOM（零 import、零 require，
  不依赖模块表，不可能再报错），server 端只保留 `/dsh-app/status`
  （App 复用探测依赖）。
- 删除：settings 注册（5 字段 schema）、`settings.section` 区块、
  `sidebar.footer.action` 入口、`ctx.settingsScope` 绑定、shell HTTP 推送。
- 删除废弃文件：`src/client/entry.ts`、`src/SettingsPanel.tsx`、
  scripts 下调试脚本、docs 下临时截图。
- package.json 的 `dsh.client.inject` 清空；server 不再依赖 schemastery。

client bundle: 13KB → 4.6KB，require 数量 0。

## 问题 5：按官方契约恢复"DSH App"设置页（关于 + 更新监测）

用户要求以插件形式注册到官方 WebUI（设置页），展示桌面端信息 + 更新监测。
第一次尝试报 `createDshAppSectionStore is not a function`，根因是
`defineStore` 的真实签名是**单参数 spec 对象** `{init, actions}`（之前传了两个参数）。

### 官方契约（从安装包源码逐条确认）
- `defineStore(spec)`：`{ init: () => T, persist?, actions: {fn(draft, ...args)} }` → StoreHandle
- 注册：`ctx.slots.inject('settings.section', () => ctx.slots.register({name, id, order, label, store, locale, inject}, Component))`
- `inject` 工厂：`(actions: BakedActions) => injected`
- locale：必须先 `ctx.locale.register(ns, {zh, en})`（声明 `locale: ns` 才有 `t` seat）
- cordis inject（服务名）必须声明 apply 里访问的所有 ctx 服务：
  `['connection', 'remote', 'settingsScope', 'locale', 'slots']` ——
  漏了 locale/slots 会抛 `cannot get property "X" without inject`
- 包级 `dsh.client.inject`（依赖包名）：runtime、locale、ui-settings，`immediately: true`
- `defineStore` 是**值导入**（external，shell 模块表提供），
  JSX 用 `react/jsx-runtime`（seed 提供）

### 实现
- Rust `app_info` 命令：返回 appVersion / dshVersion / dshSource / serviceUrl
  （ACL: build.rs + capability `allow-app-info`）
- 设置页 `settings.section` id `dsh-app`：4 行关于信息 + "检查更新"
  （npm registry `@deepseek-ai/dsh/latest` 对比本地 `dsh --version`，
  版本对比保留 prerelease 后缀）

### 实测（CDP 驱动真实面板）
- 设置面板导航出现 ["通用设置", "模型", "插件", "DSH App"] ✅
- DSH App 页：版本/CLI/来源/服务地址 4 行 ✅
